# 攻击判定与角色特效

## 设计边界

角色的 element、weapon、attackStyle 仍为互相独立的分类；真正决定命中行为的是 attackPattern。attackVisual 只定义表现，不能决定伤害。战斗代码不包含按角色ID分派的逻辑。

数据流：角色配置 → 开局快照 → 不可变战斗状态 → 纯函数判定 → 更新敌人/投射物/特效 → SVG渲染。

## 当前判定类型

| kind | 参数 | 规则 |
| --- | --- | --- |
| projectile | speed、radius、pierce | 自动瞄准射程内最近敌人，发射固定方向投射物；沿路径碰撞，最多命中1+pierce名不同敌人 |
| meleeArc | angleDegrees | 自动朝向射程内最近敌人，命中玩家周围指定角度和距离内的敌人，后方不自动受伤 |
| area | splashRadius | 选择射程内最近敌人，以其当前位置为中心造成一次范围伤害 |

射程和攻击间隔使用角色属性与武器词条合成后的数值。武器、远近程标签不强制决定判定类型；远程大剑、近战法器均可配置。元素分类暂不触发元素反应。

投射物速度单位为每50ms逻辑步的位移；到达射程或耗尽命中次数后移除。碰撞采用本步线段与敌人圆形碰撞体的首次交点，按交点顺序处理，防止高速投射物穿过敌人而漏判。每发记录已命中的敌人ID，穿透也不会重复伤害同一敌人。发射后不追踪目标，敌人移动可能躲开。

伤害与武器天赋按命中处理：近战/范围使用玩家与敌人的当步距离；投射物使用发射原点到碰撞点的距离。飞行中的投射物保留发射时伤害，不因之后选择局内强化而改变。暂停、升级和倒计时不推进投射物或特效寿命。

## 角色配置示例

- 安柏：远程弓箭，projectile，火色箭矢表现。
- 芭芭拉：远程法器，projectile，水色音符/水球表现。
- 丽莎：远程法器，area，苍雷绽放表现。
- 凯亚：近战单手剑，meleeArc（110度），霜色剑弧表现；新增到常驻池与图鉴，用于体验近战。

这是课程原型改编，不宣称复刻原作攻击机制。全部角色复用四种视觉预设，以配置颜色区分元素和角色。

## 走动、出手与受击反馈

BattleScene 负责战场图层，BattleCharacter 负责角色姿态，AttackVisuals 负责出手与攻击轨迹，EnemyPortrait 和 HitEffects 负责受击表现。角色培养和图鉴中的静态头像保持独立，不会随着战斗计时播放。

- CharacterMotion 记录是否实际移动和累计位移。碰撞移动完成后才更新，按住方向键撞墙或走到关卡边界不会原地踏步；停止移动即恢复站姿。姿态纯函数根据步距生成脚步交替、身体起伏、轻微倾斜和左右朝向。
- AttackCue 只在有合法目标且确实发起攻击时生成，保留出手时间、位置与角度。角色跟随出手方向做短暂后坐或倾斜；箭矢有拖尾与弓弦闪光，光球有像素核心与尾迹，近战显示扫动剑弧，范围攻击显示扩散波纹和粒子。
- HitEffect 来自同一敌人判定前后的实际生命差值；未命中不生成，多个投射物在同一逻辑步命中同一敌人时合并飘字。怪物短暂闪白并产生视觉抖动，粒子与伤害数字持续10步（0.5秒逻辑时间）。击杀后仍可显示击破反馈；最多保留128条，过期自动清理。
- 动作和受击位移只作用于SVG表现，碰撞坐标、射程、攻击速度和伤害仍由原判定负责。改动视觉颜色或预设不会更改战斗规则。

所有动画由不可变状态、位移和 tick 推导，不使用额外动画计时器。暂停、升级、倒计时和结束时逻辑 tick 冻结，表现同步冻结。系统开启减少动态效果时，保留命中识别和伤害数字，关闭步态起伏、抖动和扩散粒子。

当前走动是基于已有像素头像的姿态变换与简化脚步，不是完整八方向序列帧。TODO(asset-character-animation)：后续可接入独立的移动／攻击序列帧，继续消费相同的状态与出手信息。

## 配置例子

    "attackPattern": {"kind":"projectile","speed":18,"radius":4,"pierce":0},
    "attackVisual": {"name":"火色箭矢","style":"arrow","color":"#ef967b"}

表现预设 style 支持 arrow、orb、slash、burst。颜色、名称可按角色单独设置。判定与表现参数分开，改颜色或特效不会改变攻击半径、速度和伤害。当前预设根据投射物/扇形/范围输出绘制适用几何，未来可替换为角色专用素材。

## 后续如何扩展

新增角色复用已有判定时，只需添加 shared/characters.json 记录，选择判定参数与特效。已有角色换视觉，只修改 attackVisual 或扩展表现层。

需要全新判定（例如持续光束）时：

1. 扩展前端 AttackPattern 可辨识联合类型及配置校验。
2. 扩展后端 AttackPattern 枚举、对应参数对象、编解码和校验。
3. 在 resolveAttacks 添加该类型的纯函数处理；需要持续状态时新增明确的运行状态类型。
4. 给 AttackResolution 增加必要输出，由表现层消费，不在判定函数里操作DOM或播放音效。
5. 测试几何边界、目标顺序、伤害次数、生命周期和暂停恢复。

不要为每个角色创建独立伤害分支，也不要把天赋或元素反应写进特效组件。

## 验证范围

局内强化现支持随机三选一与延迟追加攻击；死亡经验改为掉落粒子吸收后加入经验条，暂停、升级与收尾阶段同步处理。完整规则见 [培养与成长](PROGRESSION.md)。

tools/verify-battle.mjs 已验证扇形角度/距离边界、线段碰撞、穿透次数与命中顺序、飞行延迟、射程耗尽、范围伤害、不重复命中，以及攻击与暂停/升级/倒计时的配合。新增验证实际位移驱动步态、撞墙／边界停步、命中才反馈、击杀标记、同帧伤害合并、暂停冻结、寿命清理、朝向和减少动态效果。关键帧已用浏览器截图检查，尚未做大量敌人的长时间性能验收。
