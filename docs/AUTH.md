# 账号、登录与管理员

## 使用

- 新用户在登录页切到注册，填写用户名、昵称、密码，注册后自动登录，默认普通用户。
- 已有体验档案到“我的账号”绑定用户名和密码，保留原用户ID与全部资产，不重复发放初始资源。
- 管理员使用相同登录入口，登录后显示管理员中心，可查看已注册账号和修改其他用户角色。
- 退出会注销账号所有登录会话。未绑定体验档案退出前有确认，建议先绑定以便重新登录。

## 首个管理员

npm run admin:setup生成.local/bootstrap-admin.env，默认用户名admin，密码为安全随机数。密码不写入源码或日志，配置文件不提交版本控制。本次已完成初始化，密码请在该文件查看。

后端通过npm脚本启动时依次加载backend/.env和本地管理员配置，已有进程环境变量优先。也可在首次启动前设置ADMIN_USERNAME与ADMIN_PASSWORD；仅当数据库没有任何管理员时创建，后续启动不会重建账号或重置密码。修改初始化配置不能改变已有密码，暂未提供修改/找回密码功能。

## 权限

| 身份 | 本人的游戏数据 | 已注册账号列表 | 修改其他账号角色 |
| --- | --- | --- | --- |
| 普通用户 | 允许 | 不允许 | 不允许 |
| 管理员 | 允许 | 允许 | 允许，记录审计 |
| 体验档案 | 允许，可绑定 | 不允许 | 不允许 |

注册接口没有角色参数，客户端自报role=admin无效。路由校验登录令牌得到可信UserId；管理员API另外调用RequireAdminMessage，以数据库角色判断，不依赖前端隐藏按钮。

角色变更通过事务锁串行处理，禁止修改自己的管理员身份，保留最后一名管理员，并记录操作者、目标、原/新角色和时间。账号列表不返回密码哈希或会话令牌；当前不提供任意SQL、删除账号或改玩家资产。

## 密码、会话与限速

- 密码使用独立16字节盐、PBKDF2-HMAC-SHA256（600000次）和256位派生值，不存明文，使用恒时字节比较。
- 登录令牌为32字节安全随机数，数据库仅存SHA-256摘要，有效期7天。退出后旧会话返回401，无管理员权限返回403。
- 用户名不存在与密码错误返回同样提示；同一用户名连续8次错误登录锁定15分钟，数据库保存失败次数。成功登录清除失败记录。
- LoginStatus是authenticated/invalid/locked封闭类型；失败登录正常返回结果，使失败计数能提交，不会因抛异常而回滚。
- 绑定后旧体验令牌停止生效，改用正式会话。CreateGuestMessage仅保留迁移兼容和既有验收工具，新用户界面不再提供体验档案创建入口。

## 表与实现

identity服务新增accounts、login_sessions、login_attempts、role_audit四张表，各自拥有Table/Initializer并记录版本。账号、密码、会话和角色规则都归identity；游戏服务只接受可信UserId。已有users及资产表不重建。

管理员初始化是后端内部API，不注册为公开路由。密码派生、随机令牌、时钟等副作用显式放在IO，资源与事务复用原数据库系统。

## 验证

node tools/verify-auth.mjs验证注册强制普通用户、重复用户名、密码校验、大小写规范化、旧存档绑定且资产不变、旧令牌失效、管理员权限、角色升降、退出和限速。工具只创建独立测试账号，不输出密码或令牌。

重启后端后，执行node tools/verify-auth.mjs check，确认账号密码和会话仍有效。测试凭据保存在.local/verification，不公开或提交版本控制。

本次实际通过：前后端构建、注册/登录/绑定/退出与角色权限验收、密码/会话摘要存储检查、重启持久化检查，以及原有角色、武器、关卡、退出和战斗逻辑回归。

当前未实现邮箱验证、密码找回、多因素认证和会话列表管理。前端仍使用localStorage存令牌，公开部署前需另行确定HTTPS与会话存储方案；账号登录不提供战斗中途续玩。
