# 初版实施与验收（2026-11-08）

## 后续更新：菜单动态地图与战斗布局

MenuMapBackground复用MapTerrain，只推进独立的展示镜头，不启动战斗模拟、生成实体或请求对局。相机按50ms定时器缓慢平移，隐藏页面或减少动态效果时停止推进，卸载清理。背景变动不更新页面业务状态。

useBattlePresentation按runId控制350ms淡出，淡出期间禁用菜单交互，完成后才挂载战斗与倒计时。战斗使用窗口内全屏布局，移除侧栏、账号、货币和说明文本，仅显示场景与BattleHUD；错误提示保留在HUD，避免结算失败后无法操作。退出或结算清除run后卸载战斗并恢复菜单。

## 后续更新：登录与角色权限

新增UserRole、LoginStatus封闭类型，注册、登录、绑定、退出、当前用户、管理员列表和角色变更API。密码加盐派生，会话摘要存储并校验到期。路由转换可信身份，管理员权限在消息内实时校验。新增四张identity表与版本，原体验档案可原ID绑定。首个管理员以本机随机密码配置初始化，不提供通用默认密码或注册时选择管理员。

## 后续更新：数据库系统完善

保留已有11张业务表，新增schema_versions。应用级Resource管理Hikari连接池，请求级Resource管理连接，事务明确处理提交、异常和取消回滚。InitializeDatabaseMessage编排服务所属初始化器，以advisory lock和版本标记避免并发/重复迁移。新增回执时间及历史索引，数据库健康检查、配置加载、建库/状态/备份脚本。静态角色与地图配置仍按原方式管理，未加入数据库管理网页或正式账号系统。

## 后续更新：祈愿动画

新增WishReveal封闭类型与独立展示阶段：gathering（850ms）→ meteor（1300ms）→ reveal。角色和武器共享展示组件，角色使用像素形象，武器显示名称、类型与主副词条。后端成功返回后才创建一次性展示事件，以请求标识作为展示序列；关闭清除事件，切页不重放旧抽取结果。

页面外层的定制dialog负责焦点和遮罩；动画中Esc/跳过直接揭晓，结果时Esc/继续按钮关闭。计时器、减少动态效果设置监听与对话框生命周期集中在hook，卸载清理。动画使用Tailwind @theme动画变量与关键帧，页面布局仍由Tailwind类组织。后台扣费与发放事务未改动，动画不会调用抽取接口。已通过TypeScript与生产构建；未做浏览器录屏验收。

## 后续更新：碰撞

新增WorldObstacle、WorldBounds及纯函数碰撞工具。地图渲染和物理共用生成配置；主循环缓存9×9物理区块，按角色、敌人半径处理移动，投射物按障碍与敌人的首次交点排序。安全生成和绕障逻辑在纯函数边界实现，既有碰撞几何从攻击函数提取共享，未引入可变物理引擎。角色与敌人之间仍是接触伤害，暂不做刚体推挤。

## 后续更新：无限冒险地图

新增MapChunk和MapDecoration封闭类型、generateChunk/nearbyChunks纯函数。世界种子与刷怪种子分离，固定25邻近区块，MapTerrain按区块坐标记忆化渲染。世界坐标统一作用于角色、敌人、攻击及装饰，SVG世界层平移实现镜头跟随；关卡视角保持固定。冒险取消120秒限制，敌人按相对位置生成并回收远敌，数量上限160；关卡不进行远敌回收。后端移除旧时长上限并更新首领生成数量的合理性检查。物件目前仅作可穿行装饰。

## 后续更新：类型化攻击判定

AttackPattern 采用前端可辨识联合与后端封闭枚举，ProjectilePattern/MeleeArcPattern/AreaPattern 各自定义参数。resolveAttacks 返回不可变 AttackResolution，包含敌人、投射物和短暂表现事件；AttackVisuals 只渲染结果。角色定义与开局快照携带两类独立配置，战斗不按角色ID分支。新增凯亚作为近战示例，卡池和图鉴自动读取。测试覆盖扫掠碰撞、扇形边界、穿透与去重、生命周期和暂停。

## 后续更新：武器系统

新增 weapons 服务，武器所有权、培养和装备分别由 WeaponTable、EquipmentTable 维护；wishes 新增独立武器保底表。content 新增武器目录与封闭词条/天赋条件类型。每个API独立文件，routes完成令牌身份转换后传入可信UserId，Table封装SQL，资源与事务复用原基础设施。

前端增加武器培养页，按库存和详情业务区域拆分；祈愿页增加角色/武器卡池切换。角色培养显示装备后数值，战斗使用开局装备快照。词条计算和条件天赋都是纯函数；反应系统未实现时明确不满足反应条件。

## 后续更新：角色配置化

新增 content 服务及七元素、五武器、远近程封闭类型，ListCharactersMessage 读取并校验共享JSON。前端从同一JSON生成角色目录，后端卡池与培养规则读取配置，开局 RunStart 与持久回执保存角色定义。本轮也修复关卡开局幂等回执写入的指纹与查询指纹不一致问题。

角色ID属于可扩展内容标识，前端不再用三角色字面量联合枚举；元素、武器和攻击类型属于封闭分类。请求去重键按角色目录初始化，新增角色不需要再修改请求键名单。武器不决定远近程，攻击执行仅使用独立配置。成长、范围与间隔已接入战斗，培养页同步显示。

## 后续更新：暂停与退出

前端 BattleAction 新增 pause/resume，暂停使用闭合状态 paused；待选强化数保留以恢复正确阶段。按 Esc、窗口失焦或点击按钮暂停，清除按键状态，取消退出后保持暂停，需点击继续。

新增 AbandonRunMessage，使用可信身份、用户行锁与现有事务，Active → Abandoned，不发奖励；重复放弃返回当前档案，已结算拒绝放弃，已放弃拒绝结算。runs 表初始化器为已有 runs_status_check 增加 abandoned 合法值，迁移位于所属表模块。verify-abandon.mjs 覆盖重复退出、身份隔离、禁止领奖及退出/结算并发竞争。

## 后续更新：关卡挑战

新增独立关卡列表及 ListStagesMessage。StartRunMessage 可接收 stageId，原请求不传时保持原有模式。run_challenges 表保存本局关卡配置及奖励快照，表由 runs 服务维护，初始化为新增表，不改动已有对局记录。清场判定和有限刷怪由纯函数处理；后端按保存的目标击杀数判定通关并决定奖励，失败为零奖励。已有客户端战果信任限制仍然存在，不宣称能验证完整战斗。

关卡可重复挑战，每次通关均发奖励，单局由已有状态锁与事务防止重复发放。新增 tools/verify-stages.mjs 验证关卡配置、失败无奖励、通关奖励和并发领取保护。

## 实际实现

- React + TypeScript + Tailwind 冒险营地，角色卡、余额、培养、祈愿与结果反馈。
- 纯函数战斗状态转换，SVG 渲染，WASD/方向键移动；每 50ms 一次固定逻辑步。
- 120 秒单人试炼，自动范围攻击、追踪敌人、90 秒出现首领、每 8 次击杀二选一强化。
- 局外每升 3 级增加 1 点开局攻击；当前角色之间主要是主题差异，尚无独立技能。
- PostgreSQL 持久体验档案；初始安柏、1600 原石、5000 摩拉。
- 祈愿已按稀有度抽取：角色池五星0.6%、四星5.1%，武器池五星0.7%、四星6%；分别采用90／80抽五星上限和10抽四星或以上保障，并接入注明来源的软保底模型。角色池可出武器；武器池仅出武器，详细改编范围见 [祈愿规则](WISHES.md)。
- 重复角色记录印记；500 摩拉升级，20 级上限。
- 战斗结束获得 40 原石、200+击杀数×10 摩拉；服务端校验归属、基本范围和时间。
- 玩家账户行锁串行化资产变更；数据库事务保证扣款、发放、保底与流水一致。
- 抽卡/强化/开局使用持久幂等回执，客户端失败后保留当前请求标识以便重试；重新加载页面后没有完整的待处理请求恢复功能。
- 同一局重复结算不重复发奖，不同战果重复提交拒绝。

## 尚未实现

## 规则落实与边界

- 后端所有代码归属 services；每个服务只使用 api、objects、routes、tables、utils。
- API 为独立 final case class，唯一执行入口 plan(connection): IO[Response]；路由解析 token 得到可信 UserId。
- 无身份的体验档案创建是公开操作；体验 token 是持有者凭证，保存在浏览器本地，尚无正式会话过期/撤销系统。
- 每张表拥有 Table 与 Initializer，SQL 私有且邻接方法；JDBC 通过 Resource 管理，IO 延迟副作用，无业务层执行运行时。
- RunStatus 使用封闭枚举；标识由 UserId、CharacterId、RunId 区分。部分数据库/传输字段保留字符串，在未来细化内容域时继续加强。
- API 专用结果放 objects/apiTypes；传输与数据库对象独立文件。
- system 的 RouteRegistration 包含函数，是路由基础设施，不是可序列化业务数据；无需为函数派生 JSON 编解码。
- system 的 operation_receipts 是跨业务请求去重基础设施；wishes 维护保底，角色表维护印记，economy 维护余额和流水。
- 初版通过 GetProfileMessage 汇总余额、角色和保底，属于首页聚合读接口；后续领域扩展时可拆细查询，但不建立仅转发的 Service 层。
- React 入口展示业务区域，状态放 hook；战斗 reducer 不访问随机数、时钟或 DOM。计时器、按键、HTTP、本地 token 操作保留在边界。
- SVG 中坐标和颜色是画布属性，页面样式使用 Tailwind；没有手写布局 CSS。

## 验证

已实际通过：Scala 编译、TypeScript 检查、Vite 生产构建、纯战斗逻辑检查，以及本地 PostgreSQL + HTTP API 验收。

API 验收覆盖：初始资源、相同请求并发抽卡/升级只执行一次、请求标识冲突拒绝、他人对局不能领取、相同对局重复结算不重复发奖、不同结果重复结算拒绝、并发抽卡余额不为负、角色／武器混合奖励正确入账。保底不再保证补齐收藏。

战斗逻辑检查覆盖：同输入确定性、输入未修改、地图边界、升级期间暂停、结束后冻结、死亡击杀不重复累计。

未进行浏览器截图验收、长时间性能测试或完整手动通关。前端战果不能证明真实战斗，当前实现不是防作弊系统。
